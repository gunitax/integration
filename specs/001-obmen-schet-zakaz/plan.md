# Implementation Plan: Обмен «Счет на оплату покупателю» → «Заказ»

**Branch**: `001-obmen-schet-zakaz` | **Date**: 2026-11-08 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-obmen-schet-zakaz/spec.md`

## Summary

Сквозной обмен документами: выгрузка счёта на оплату покупателю (bsp, `_ДемоСчетНаОплатуПокупателю`) в топик Kafka и загрузка его в заказ (uf_demo, документ «Заказ») с сопоставлением существующих справочников, обновлением без дублей, ведением протокола и сверкой. Реализация — два новых расширения по прецедентам работающих обменов товарами: `ЭкспортСчетовВШину` (`ЭСВ_`) в `bsp` и `ИмпортСчетовИзШины` (`ИСШ_`) в `uf_demo`; приёмник повторяет паттерн ИТШ (внешняя компонента librdkafka, ручной коммит офсетов при порции без ошибок). Сверка — в базе БСП отчётом по образцу сверки товаров (решение пользователя): HTTP-сервис приёмника отдаёт заказы (расширение существующего `ИТШ_Товары` по явному указанию пользователя), срез сохраняется в регистре источника `СС_СостояниеЗаказовПриемника`, отчёт СКД `СС_СверкаЗаказов` сравнивает счета со срезом; публикация uf-demo-test на Apache настраивается и проверяется в рамках фичи; далее Vanessa-фичи по обеим базам и PDF-инструкция из скриншотов Vanessa.

## Technical Context

**Primary Dependencies**: расширение СШП (`bsp`) с внешней компонентой librdkafka (`AddIn.librdkafka.KafkaProducer/KafkaConsumer`), брокер Kafka `localhost:9092` (тестовая среда), Vanessa Automation 1.2.043.42 + VAExtension 1.32, скиллы `.zcode/skills/` (cfe-init, make-cfe, db-cfe-admin, bsl-code-standards, bsl-queries)

**Storage**: файловые информационные базы: источник `C:\Users\sax\Documents\InfoBase22` (БСП), приёмник `C:\Users\sax\Documents\uf-demo-test`; срез заказов приёмника для сверки хранится в регистре источника `СС_СостояниеЗаказовПриемника` (расширение СверкаСправочников); приёмник публикуется на Apache (`C:\Apache24`, `http://localhost/uf-demo-test/hs/...`)

**Testing**: Vanessa Automation — фичи `bsp/Vanessa/features/scheta/` (экспорт — прогоны `va.ps1`/`smoke-infobase22.ps1` на InfoBase22; импорт/сверка — `va-nouser.ps1` на uf-demo-test); синтаксический контроль — `db-cfe-admin check` (apply,modules,config в контекстах ThinClient/Server/ExternalConnection)

**Target Platform**: тонкий клиент + сервер 1С под Windows x86_64; брокер Kafka на localhost

**Project Type**: расширения конфигурации 1С (CFE) с внешней компонентой Native API

**Performance Goals**: не заданы (демо-объёмы); выгрузка и загрузка — порциями (размер порции 100 сообщений, таймаут чтения пула 5 с — по прецедентам ЭТШ/ИТШ)

**Constraints**: только ручной запуск (без регламентных заданий); существующие модули и механизмы обмена товарами (`goods`) не изменяются; расширения самодостаточны; UTF-8 BOM + CRLF; без «ё» в именах метаданных; заказы не проводятся

**Scale/Scope**: 2 новых расширения (~6 модулей, 3 обработки с формами, 1 справочник-эталон, 4 макета ВК), 3–4 Vanessa-фичи, 1 PDF-инструкция

```text
    └── scheta-manual.feature

```

**Structure Decision**: два независимых расширения по одному на сторону обмена — повторяет проверенную компоновку ЭТШ/ИТШ (разделение ответственности источник/приёмник, изолированный `/CheckConfig` каждого расширения, независимые префиксы). Сверка размещается в источнике (расширение СверкаСправочников, по образцу товарной сверки СС_): отчёт сравнивает локальные счета со срезом заказов, полученным по HTTP-сервису приёмника; HTTP-шаблон заказов добавляется в существующий сервис приёмника по явному указанию пользователя.
