# Data Model: Обмен «Счет на оплату покупателю» → «Заказ»

Дата: 2026-11-08. Источник: [spec.md](spec.md) (включая Clarifications), [research.md](research.md).

## Существующие объекты (не изменяются)

### Счёт на оплату покупателю — источник

`Документ._ДемоСчетНаОплатуПокупателю` (bsp, формат 2.20)

| Поле | Тип | Участие в обмене |
|------|-----|------------------|
| Номер | Строка 11 (периодичность Год) | Передаётся; приёмник усекает до 9 |
| Дата | Дата | Передаётся (ISO-строка в JSON) |
| Организация | `CatalogRef._ДемоОрганизации` | Наименование (полное, до 150) |
| Контрагент | `CatalogRef._ДемоКонтрагенты` | Наименование (полное, до 50) — clarify Q1 |
| ВалютаДокумента | `CatalogRef.Валюты` | Код (3) + Наименование (до 10) — clarify Q2 |
| Товары.Номенклатура | `CatalogRef._ДемоНоменклатура` | Артикул (до 25), Наименование (до 100), Штрихкод |
| Товары.Количество | Число 15,3 | Число в JSON |
| Товары.Цена, Товары.Сумма | Число (ДенежнаяСуммаНеотрицательная) | Числа в JSON |
| Товары.Характеристика | `CatalogRef._ДемоХарактеристики` | Не передаётся |

Сумма документа = Σ Товары.Сумма (реквизита суммы шапки в источнике нет — FR-004). Партнёр, валюта взаиморасчетов, НДС, скидки — не участвуют.

### Заказ — приёмник

`Документ.Заказ` (uf_demo, формат 2.21)

| Поле | Тип | Заполнение |
|------|-----|------------|
| Номер | Строка 9, уникальный | Обрезанный номер счёта |
| Дата | Дата (обязателен) | Дата счёта |
| Покупатель | `CatalogRef.Контрагенты` (обязателен) | Сопоставление по наименованию (до 30, строгое) |
| Организация | `CatalogRef.Организации` (обязателен) | Наименование (до 25, строгое) |
| Валюта | `CatalogRef.Валюты` (обязателен) | Код (3) → Наименование |
| Сумма | Число 10,2 | Σ строк сообщения |
| Склад | `CatalogRef.Склады` (обязателен) | Первый непомеченный склад, `НеИспользовать = Ложь` |
| СостояниеЗаказа | `EnumRef.СостоянияЗаказов` | `Открыт` |
| Posted | стандартный | Ложь — никогда не проводится (FR-006) |
| Товары.Товар | `CatalogRef.Товары` | Артикул (15) → Штрихкод (20) → Наименование (50, строгое) |
| Товары.Количество | Число 10,0 | Цел() из 15,3, предупреждение при дробном |
| Товары.Цена, .Сумма | Число 10,2 | Как в сообщении; переполнение — протокол-ошибка |

## Новые объекты

### Справочник ИСШ_СчетаОбмена — эталон сверки (uf_demo, расширение ИСШ_)

Реквизиты: `Номер` (Строка 9), `ДатаСчета` (Дата), `Организация` (Строка), `Покупатель` (Строка), `ВалютаКод` (Строка 3), `ВалютаНаименование` (Строка), `Сумма` (Число 15,2). ТЧ `Товары`: `Артикул` (Строка), `Наименование` (Строка), `Штрихкод` (Строка), `Количество` (Число 15,3), `Цена` (Число 15,2), `Сумма` (Число 15,2).

- Идентификация: `Номер + ДатаСчета` (idempotent — при повторной загрузке обновляется).
- Пишется для каждого прочитанного сообщения: загруженного и пропущенного по протоколу (R-6) — иначе сверка не увидит ожидаемое отсутствие документа.
- Наименование элемента: `Номер от ДД.ММ.ГГГГ` (навигация в списке).

### Правила валидации и переходы

| Правило | Источник |
|---------|----------|
| Заказ идентифицируется парой Номер+Дата; дублей нет | FR-007 |
| Номер длиннее 9 — обрезка + предупреждение | Edge Cases |
| Количество дробное — Цел() + предупреждение | Edge Cases |
| Цена/сумма вне 10,2 — протокол-ошибка, документ не записывается | Edge Cases |
| Наименование длиннее поля приёмника — «не найдено», без обрезки | Clarify Q5 |
| Ненайденный элемент — пропуск документа целиком (и создание, и обновление) | FR-009, FR-008 |
| Заказ с пометкой удаления — пропуск, пометка сохраняется | Clarify Q4 раунда 1 |
| Счёт с пометкой удаления — не выгружается, запись в протокол | Clarify Q3 раунда 1 |
| Ошибка в порции — офсеты не коммитятся, сообщение повторится | R-3 (прецедент ИТШ) |

## Структуры итогов (контракты модулей)

- Экспорт: `Отправлено` (Число), `Ошибок` (Число), `Протокол` (Массив строк).
- Загрузка: `Прочитано`, `Создано`, `Обновлено`, `Пропущено`, `Ошибок` (Числа), `Протокол` (Массив строк).
- Сверка: `Проверено` (Число эталонов), `Совпало`, `Расхождений` (Числа), `Отчет` (Массив строк статусов).
