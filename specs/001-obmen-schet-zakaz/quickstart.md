# Quickstart: ручная проверка обмена «Счёт → Заказ»

Дата: 2026-11-08. Предполагается, что расширения загружены в базы и проверены (`db-cfe-admin check`), брокер Kafka запущен на `localhost:9092`, в приёмнике сняты «Безопасный режим» и «Защита от опасных действий» для `ИмпортСчетовИзШины`.

## Предпосылки

- Источник: `C:\Users\sax\Documents\InfoBase22` (БСП, пользователь «Администратор») с расширениями `ЭкспортСчетовВШину` и `СверкаСправочников`.
- Приёмник: `C:\Users\sax\Documents\uf-demo-test` (пользователей нет) с расширениями `ИмпортСчетовИзШины` и `ИмпортТоваровИзШины`.
- Публикация приёмника на Apache: `http://localhost/uf-demo-test` (для HTTP-среза сверки).
- Справочники приёмника наполнены элементами, наименования которых совпадают с данными счёта (см. правила в [contracts/invoice-message.md](contracts/invoice-message.md)); товары уже могут быть созданы обменом `goods`; склад приёмника — первый непомеченный используемый.

## Сценарий 1: сквозной обмен нового счёта

1. В источнике открыть обработку «Выгрузка счетов в шину» (`ЭСВ_ВыгрузкаСчетов`). Адрес `localhost:9092`, топик `invoices` — значения по умолчанию.
2. Задать период, убедиться, что счёт отмечен, нажать «Выгрузить».
   Ожидаемо: «отправлено 1, ошибок 0».
3. В приёмнике открыть «Загрузку счетов из шины» (`ИСШ_ЗагрузкаСчетов`): адрес/группа/топик — по умолчанию, нажать «Загрузить».
   Ожидаемо: «прочитано 1, создано 1, ошибок 0» (или «пропущено 1» с ненайденными элементами в протоколе — новые элементы при этом не появляются).
4. Открыть список «Заказы»: заказ с номером счёта (до 9 символов), датой счёта, организацией, покупателем, валютой; строки — как в счёте; заказ **не проведён**, состояние «Открыт».

## Сценарий 2: повторная загрузка без дублей

5. Снова нажать «Загрузить» в приёмнике (то же сообщение).
   Ожидаемо: «обновлено 1», количество заказов не изменилось, содержимое заказа совпадает со счётом.
6. Изменить счёт в источнике (количество/цена строки, добавить/удалить строку), выгрузить снова, загрузить в приёмнике.
   Ожидаемо: заказ приведён в соответствие; сверка (сценарий 3) показывает «Совпадает».

## Сценарий 3: сверка (в базе источника, по HTTP-срезу приёмника)

7. В источнике (InfoBase22) открыть «Обновление среза заказов» (`СС_ОбновлениеСрезаЗаказов`), адрес публикации `http://localhost/uf-demo-test/hs/itsh-goods/v1/orders` — по умолчанию, нажать «Загрузить срез».
   Ожидаемо: сообщение о количестве записей среза (`СС_СостояниеЗаказовПриемника`).
8. Открыть отчёт «Сверка заказов с приёмной базой» (`СС_СверкаЗаказов`), задать период по дате счёта, «Сформировать».
   Ожидаемо: согласованные строки — «Совпадает» (скрыт отбором по умолчанию); расхождение после правки заказа — «Расходится»; счёт без заказа — «Нет в приёмнике»; счёт с пометкой удаления — «Счёт помечен на удаление».

## Автоматические проверки (Vanessa)

```powershell
# экспорт + сверка (база InfoBase22, Vanessa с предзапуском TestClient)
powershell -File bsp\vanessa\va.ps1 -Feature bsp\Vanessa\features\scheta\scheta-export.feature -BasePath C:\Users\sax\Documents\InfoBase22 -PreLaunchClient
powershell -File bsp\vanessa\va.ps1 -Feature bsp\Vanessa\features\scheta\scheta-sverka.feature -BasePath C:\Users\sax\Documents\InfoBase22 -PreLaunchClient
# импорт (база uf-demo-test, без /N)
powershell -File bsp\vanessa\va-nouser.ps1 -Feature bsp\Vanessa\features\scheta\scheta-import.feature
```

`scheta-import.feature` сам делает экспорт источника через COM (счёт «ИНТ-1001» фиксирован — сценарии повторяемы); проверки строятся на `Ошибок = 0` и содержимом заказов, а не на количестве сообщений в топике (офсеты группы живут в брокере). Прогон Vanessa на этой машине — только с `-PreLaunchClient` (без флага TestClient не подключается).

## Критерии готовности (из спеки)

- SC-001: цикл «выгрузка → загрузка → заказ» — два ручных запуска.
- SC-002: повторная загрузка не увеличивает количество заказов.
- SC-003: после изменения счёта сверка показывает 0 расхождений.
- SC-004: все ненайденные элементы — в протоколе, новых элементов справочников нет.
- SC-005: Vanessa-фичи проходят без ошибок.
- SC-006: PDF-инструкция покрывает операции сценариев 1–3.
