Код BSL в этом репозитории пишется и ревьюится по стандартам 1С (v8std). Контекст: демонстрационная БСП 3.1.12.348, платформа 8.3.27, управляемое приложение, встроенный язык русский, стиль БСП (см. таблицу суффиксов модулей в AGENTS.md). Правки — текстом в выгрузке: UTF-8 с BOM, CRLF, заголовок лицензии CC BY 4.0 сохранять, вместо «ё» — «е» (AGENTS.md). Доработки — в расширениях, если явно не указано иное. Запросы (написание и индексы) — отдельный скилл `bsl-queries`, здесь не дублируются.

## Именование (std550, std454, std456)

- Имена объектов метаданных: КэмелКейс без пробелов, существительное по предметной области («Валюты», а не «СправочникВалюты»); уникальность имени — по всей конфигурации; синоним — представление для пользователя. Состав метаданных меняется только в Конфигураторе (правило 6 AGENTS.md).
- Переменные и параметры: по предметной области, самодокументируемые. Венгерская нотация и бессмысленные префиксы (`м`, `ф`, `стр`, `чсл`) запрещены. Короткие имена допустимы только для счетчиков циклов (`Сч`, `ИндексСтроки`) — и то лучше по смыслу.
- Процедуры и функции: глагол или существительное + глагол (`ПолучитьОстатки`, `ЗаписьДокумента`); не начинать с недействующей части слова. Функции, возвращающие булево, — через причастие/прилагательное: `ТребуетсяПересчет`, `ПризнакПросрочен`.
- Имена процедур и функций не должны противоречить поведению (`ПрочитатьФайл`, делающий запись, — плохое имя).

## Структура модуля (std455)

Шаблоны областей (области объявлять в этом порядке, пустые области не оставлять):

- Общий модуль: `ПрограммныйИнтерфейс`, `СлужебныйПрограммныйИнтерфейс`, `СлужебныеПроцедурыИФункции`.
- Модуль объекта/менеджера/набора записей/обработки/отчета: то же + `ОписаниеПеременных`, `ОбработчикиСобытий`, `Инициализация`.
- Модуль формы: `ОписаниеПеременных`, `ОбработчикиСобытийФормы`, `ОбработчикиСобытийЭлементовШапкиФормы`, `ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>`, `ОбработчикиКомандФормы`, `ПрограммныйИнтерфейс`, `СлужебныеПроцедурыИФункции`.
- Модуль команды: `ОбработчикиСобытий`.

Правила: программный интерфейс — сразу после переменных, служебные — в конце; обработчики событий не вызывать из кода напрямую (вынести логику в обычную процедуру); порядок подчиненных областей сохранять; при вставке новой процедуры — в правильную область, а не в конец модуля.

## Процедуры, функции, комментарии (std453)

- Doc-комментарий над объявлением каждой экспортной процедуры/функции: назначение, раздел `Параметры:` (имя — тип и описание, по одному на строку), `Возвращаемое значение:` для функций. Нестандартные параметры — `// см. <имя процедуры>`.
- Одна процедура — одна задача; большие процедуры (сотни строк, глубокая вложенность > 3 уровней) — дробить.
- Дублирующийся код (2+ близких копии) — выносить в общий модуль.

## Общие модули (std469)

- Создавать по одному признаку объединения (объект, подсистема, тип встраивания), не «свалки» вроде `РазноеСервер`.
- Суффиксы контекста — по таблице AGENTS.md (`Клиент`, `КлиентСервер`, `ВызовСервера`, `ПовтИсп`, `Переопределяемый`, `Служебный`, `Глобальный`).
- `ПовтИсп` — только для данных, зависящих от информационной базы, но не от сеанса/пользователя; вызовы из таких модулей не должны давать побочных эффектов.
- Служебные модули (`Служебный`) — не использовать из прикладного кода.

## Конструкции языка

Исключения (std «Перехват исключений в коде», «Вызов исключений в коде»):
- Пустой блок `Исключение` / `ПродолжитьВыполнение` без обработки — запрещен. Ловить только ожидаемые ошибки конкретного участка.
- Шаблон с журналированием и пробросом:

```bsl
Исключение
    ЗаписьЖурналаРегистрации(ИмяСобытия(), УровеньЖурналаРегистрации.Ошибка,,,
        ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    ВызватьИсключение;
КонецПопытки;
```

- Пользовательский текст исключения — `НСтр("ru = 'Текст ошибки.';")`.
- Сообщения пользователю — `ОбщегоНазначения.СообщитьПользователю` (сервер) или `ОбщегоНазначенияКлиентСервер.СообщитьПользователю`; метод `Сообщить` запрещен (std «Ограничение на использование метода Сообщить»). Оба модуля есть в этой БСП (проверено).
- Ошибки фоновых и регламентных заданий всегда писать в журнал регистрации (std «Использование ЖурналаРегистрации»).
- `Перейти` — запрещен.
- Перенос выражений (std «Перенос выражений»): логические/арифметические операторы — в начале строки продолжения; переносы выравнивать по оператору.

Типы, даты, строки, коллекции:
- Тип проверять `ТипЗнч(Значение) = Тип("...")`, заполненность — `ЗначениеЗаполнено()`, а не сравнением с литералами.
- Даты: `НачалоДня`, `КонецДня`, `НачалоМесяца`... вместо арифметики (`Дата + 86399` — запрещено). Отбор по периоду: `Дата >= &Начало И Дата < &Конец`.
- Строки сообщений — `СтрШаблон("Текст: %1", Значение)`, не конкатенацией; массовую конкатенацию (> ~10 строк) — собирать в массив/таблицу и `СтрСоединить` (std «Массовая конкатенация строк»).
- Поиск в больших коллекциях в цикле — через `Соответствие`, а не линейным перебором (std «Поиск в коллекциях»).
- Запись одной записи независимого регистра сведений — `РегистрыСведений.<Имя>.СоздатьМенеджерЗаписи()` (std «Использование РегистрСведенийМенеджерЗаписи»).
- Ответственное чтение (std648): читать данные по ссылке через запрос; перед обработкой проверять, что ссылка не пустая и объект существует.

## Транзакции и блокировки (std783)

- Единственный правильный шаблон; начало, фиксация и откат — в одном методе, без вызова «снаружи»:

```bsl
НачатьТранзакцию();
Попытка
    // запись данных
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

- Не открывать транзакцию на клиенте; не вкладывать `НачатьТранзакцию` друг в друга; не открывать транзакцию, если запись не требуется.
- Внутри транзакции после исключения не обращаться к базе данных (ошибка «В данной транзакции уже происходили ошибки»); взаимодействия с пользователем, файлы, почта, сеть — вне транзакции.
- Все проверки корректности — до изменения данных и по возможности вне транзакции (std463).
- Блокировки — управляемые: `Новый БлокировкаДанных` + `Заблокировать()` перед изменением данных (std «Использование управляемого режима блокировки»); `Объект.Заблокировать()` не использовать. В этой выгрузке помните про hotfix фичи 002: блокировки через `Новый БлокировкаДанных`.

## Клиент-серверное взаимодействие и формы

- Минимизировать число серверных вызовов и объем передаваемых данных (std «Минимизация количества серверных вызовов и трафика»): собирать данные пакетом, возвращать структуру, а не вызывать по значению.
- В модулях форм по умолчанию `&НаСервереБезКонтекста`; контекстный вызов — только когда нужны данные формы. Настройки формы — в `ПриСозданииНаСервере`, а не на клиенте в `ПриОткрытии`.
- Кэширование — модули `ПовтИсп`, а не реквизиты формы.
- Модальные окна и синхронные вызовы (`Вопрос`, `ОткрытьМодальноФорму`, `ПоместитьФайл`...) запрещены (std «Ограничение на использование модальных окон и синхронных вызовов») — `ПоказатьВопрос`, `ПоказатьПредупреждение`, асинхронные `Начать...`/`Показать...` с `ОписаниеОповещения`.
- Открытие форм (std404): `ОткрытьФорму(ИмяФормы, Параметры, Владелец)`; `ПолучитьФорму().Открыть()` — не использовать. Данные в форму передавать параметрами формы.
- В обработчиках объекта (`ПередЗаписью`, `ОбработкаПроведения`, обработчиках формы) при неудаче проверки — `Отказ = Истина` и никаких записей в базу после отказа (std «Работа с параметром Отказ в обработчиках событий»).

## Чек-лист написания/ревью кода

1. Файлы: UTF-8 с BOM, CRLF, заголовок CC BY 4.0 на месте, «е» вместо «ё».
2. Области модуля по шаблону std455, обработчики не вызываются вручную, doc-комментарии у экспортных.
3. Нет: `Сообщить`, модальных и синхронных вызовов, `Перейти`, пустых `Исключение`, арифметики дат, венгерских префиксов.
4. Транзакции по std783, блокировки через `БлокировкаДанных`.
5. Серверные вызовы минимальны, `&НаСервереБезКонтекста` по умолчанию.
6. Есть запросы — подключить скилл `bsl-queries` (в т.ч. проверка индексов std652).
7. Новые объекты метаданных — только в Конфигураторе, потом выгрузка в репозиторий.
