Сборка .cf текущей конфигурации (выгрузка в корне репозитория) через одноразовую пустую файловую базу: база создаётся, в неё грузятся файлы, выгружается .cf, база удаляется. Основная база и репозиторий не изменяются.

## Запуск

Скрипт: `.zcode\skills\make-cf\scripts\make-cf.cmd`

- Через Bash tool только с `run_in_background: true` (полный цикл ~10-15 мин, обычный лимит вызова — 10 мин); завершение ждать через TaskOutput.
- Аргумент: путь к итоговому .cf. Не задан — скрипт сам берёт имя из спецификации: `.specify/feature.json` → `feature_directory` → `build\<имя-фичи>.cf`. Относительный путь считается от корня репозитория, `.cf` дописывается при отсутствии.

## Что делает скрипт

1. Удаляет старые временные базы `%TEMP%\1c-cf-build-*` (в т.ч. оставшиеся после убитых по таймауту запусков).
2. Находит последнюю платформу в `C:\Program Files\1cv8\*\bin\1cv8.exe`.
3. `CREATEINFOBASE File=...` — пустая файловая база в `%TEMP%`.
4. `DESIGNER /LoadConfigFromFiles <корень репо>` (~7 мин на полный дамп БСП).
5. `DESIGNER /DumpCfg <выход>.cf`.
6. Всегда удаляет временную базу, в том числе при ошибке; при ошибке печатает логи load.log/dump.log.

## Проверка результата

- Успех = `exit 0` **и** .cf существует с размером > 0. Пустой лог `/Out` — не признак успеха (платформа может упасть до начала логирования).
- Если Bash-таймаут убил скрипт: временная база остаётся в `%TEMP%` и процесс 1cv8 мог остаться в памяти — руками ничего не убивать (taskkill по образу может зацепить Конфигуратор пользователя), просто перезапустить скрипт: он сам подчистит и пересоздаст базу.
