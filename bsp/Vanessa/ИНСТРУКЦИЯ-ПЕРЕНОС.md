# Vanessa Automation: перенос в другой проект

Инструкция к архиву `Vanessa-Automation-Kit-20261102.zip`. Описывает, как развернуть
сценарные тесты Vanessa Automation (ВА) в другой базе 1С и как запускать их без этого проекта.
Все пути в командах даны как `$env:USERPROFILE\Vanessa` — каталог, который получится после
распаковки архива (см. шаг 1).

## 1. Что в архиве

| Путь от корня архива | Содержимое | Нужно в новом проекте |
| --- | --- | --- |
| `Vanessa/va.ps1` | раннер: менеджер тестирования и тестовый клиент | обязательно |
| `Vanessa/tools/vanessa-automation-single.epf` | обработка ВА 1.2.043.42 | обязательно |
| `Vanessa/tools/VAExtension.1.32.cfe` | расширение ВА для тестируемой базы | обязательно |
| `Vanessa/install/Загрузить-VAExtension.ps1` | загрузка и применение расширения в базу | обязательно |
| `Vanessa/features/smoke/bsp-demo-smoke.feature` | рабочий дымовой сценарий, образец синтаксиса | как образец |
| `Vanessa/features/` | 179 сценариев стенда УТ 11, каталог `diagnostics`, снимки | как образцы приемов |
| `Vanessa/scripts/` | `onec.py`, va-скрипты стенда, закреп `vanessa.json` (версии и SHA-256) | справочно |

Полный объем — около 3,3 тыс. файлов и 349 МБ, из них 219 МБ — диагностические
распакованные исходники EPF в `reports/1c/tmp`. Сам архив `Vanessa-Automation-Kit-20261102.zip`
занимает 149 МБ. Для работы достаточно набора из раздела 8.

## 2. Требования

- Windows, PowerShell 5.1 (входит в систему).
- Платформа 1С 8.3.27 (проверено на 8.3.27.2325): `1cv8c.exe` для менеджера тестирования,
  `1cv8.exe` для пакетных команд конфигуратора. Версия клиента должна совпадать с версией
  сервера, иначе менеджер не подключится: «Несоответствие версий клиента и сервера».
- Серверная информационная база (не файловая): раннер подключается строкой `/S <сервер>\<база>`,
  а тестовый клиент — строкой `Srvr="<сервер>";Ref="<база>";`.
- Пользователь с правами администратора и с возможностью менять конфигурацию базы:
  расширение `VAExtension` надо загрузить и применить.
- Свободные TCP-порты из диапазона `-ClientPort` (по умолчанию 48050–48099).

## 3. Установка в новый проект

### Шаг 1. Распаковать архив

Распакуйте архив в короткий путь: в полном архиве есть глубокие диагностические каталоги,
и при распаковке в длинный каталог появляется «Слишком длинный путь или имя файла» (предел —
260 символов на полный путь к файлу). Подойдет профиль пользователя:

```powershell
Expand-Archive -Path Vanessa-Automation-Kit-20261102.zip -DestinationPath $env:USERPROFILE
```

Получится `C:\Users\<пользователь>\Vanessa`; дальше в примерах этот каталог обозначен как
`$env:USERPROFILE\Vanessa`. Скрипты используют свой каталог (`$PSScriptRoot`), а пути с пробелами
обрабатываются, поэтому проект можно держать и в `C:\Мои проекты\Vanessa`, если хватает длины пути.

### Шаг 2. Проверить файлы и версию платформы

```powershell
Get-FileHash $env:USERPROFILE\Vanessa\tools\vanessa-automation-single.epf -Algorithm SHA256
Get-FileHash $env:USERPROFILE\Vanessa\tools\VAExtension.1.32.cfe -Algorithm SHA256
```

Ожидаемые суммы:

| Файл | SHA-256 |
| --- | --- |
| `vanessa-automation-single.epf` | `92675132e3b59e9cb492f4202746d29455c108cd6c9e0751c7c3e950080239e0` |
| `VAExtension.1.32.cfe` | `3a90c163f7b7c4852e2a74a1fb4270276310add974fbe443059152e7417e1fc4` |
| `client_mcp.cfe` | `d1093475a15e50a33ad48a64b61d09d1108b5a39328c73e6be17a5c914825e7f` |

Клиент 1С раннер выбирает сам, в таком порядке: параметр `-Exe`; переменная среды
`VANESSA_1C_EXE` (путь к `1cv8c.exe`); самая новая версия из `C:\Program Files\1cv8\<версия>\bin`,
у которой установлены и клиент, и сервер (ragent.exe). Версия клиента должна совпадать
с версией сервера, поэтому установка только клиента 8.5.1 при сервере 8.3.27 не подходит:
для такого случая есть `-Exe`.

### Шаг 3. Загрузить расширение в свою базу

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File $env:USERPROFILE\Vanessa\install\Загрузить-VAExtension.ps1 `
    -Connection 'srv1\МояБаза' -User 'Администратор'
```

Скрипт выполняет три команды конфигуратора и пишет логи в `install/`:

1. `/LoadCfg tools\VAExtension.1.32.cfe -Extension VAExtension` — загрузка расширения;
2. `/UpdateDBCfg -Extension VAExtension` — применение в базу;
3. `/CheckConfig -Extension VAExtension` — проверка, ожидается «Ошибок не обнаружено».

Если у пользователя есть пароль, добавьте `-Password '...'`. Повторный запуск безопасен:
загрузка заменяет расширение с тем же именем.

Эквивалент вручную:

```powershell
$exe = 'C:\Program Files\1cv8\8.3.27.2325\bin\1cv8.exe'   # ваша версия сервера
$opt = @('DESIGNER','/S','srv1\МояБаза','/N','Администратор','/DisableStartupDialogs','/DisableStartupMessages')
Start-Process -FilePath $exe -Wait -ArgumentList ($opt + @(
    '/LoadCfg',"$env:USERPROFILE\Vanessa\tools\VAExtension.1.32.cfe",'-Extension','VAExtension',
    '/Out',"$env:USERPROFILE\Vanessa\install\VAExtension-load.log"))
Start-Process -FilePath $exe -Wait -ArgumentList ($opt + @(
    '/UpdateDBCfg','-Extension','VAExtension','/Out',"$env:USERPROFILE\Vanessa\install\VAExtension-update.log"))
```

Запускайте конфигуратор через `Start-Process -Wait`. Через `&` PowerShell не дожидается
завершения, два запуска накладываются и второй падает с «Ошибка блокировки информационной
базы для конфигурирования».

### Шаг 4. Подготовить сценарий

Скопируйте образец и поправьте под свою базу: имя TestClient в контексте должно совпадать
с параметром `-Profile`, ссылки и заголовки — с вашей конфигурацией.

```gherkin
# language: ru
Функционал: Дымовой прогон Vanessa Automation

Контекст:
	Дано я подключаю TestClient "Демо" логин "Администратор" пароль ""

Сценарий: Открытие списка номенклатуры
	И я открываю навигационную ссылку "e1cib/list/Справочник.Номенклатура"
	Тогда открылось окно "Номенклатура"
	И я закрываю все окна клиентского приложения
```

Файл — UTF-8, отступы — табуляция, первая строка `# language: ru`.

### Шаг 5. Запустить прогон

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File $env:USERPROFILE\Vanessa\va.ps1 `
    -Feature $env:USERPROFILE\Vanessa\features\smoke\bsp-demo-smoke.feature `
    -Connection 'srv1\МояБаза' -Srvr 'srv1' -Ref 'МояБаза' `
    -User 'Администратор' -Profile 'Демо'
```

Первый прогон удобно сделать с параметрами по умолчанию (`localhost\bsp_demo`), если такая база
есть: так отделяется проблема окружения от проблемы сценария.

## 4. Параметры раннера va.ps1

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `-Feature` | обязательный | путь к `.feature`; может быть каталогом сценариев |
| `-Profile` | `Демо` | имя TestClient из контекста сценария |
| `-User` | `Администратор` | пользователь базы для менеджера и тест-клиента |
| `-Connection` | `localhost\bsp_demo` | строка `/S` для менеджера тестирования |
| `-Srvr` | `localhost` | сервер в строке соединения тест-клиента |
| `-Ref` | `bsp_demo` | имя базы в строке соединения тест-клиента |
| `-ClientPort` | `48050` | первый порт диапазона тест-клиента (занимает 50 портов) |
| `-TimeoutMinutes` | `10` | предел ожидания менеджера, потом свой процесс останавливается |
| `-Exe` | автоопределение | путь к `1cv8c.exe` конкретной версии; альтернатива — переменная `VANESSA_1C_EXE` |

Что делает раннер: создает `reports/run-<дата-время>`, пишет `VAParams.json`, запускает
`1cv8c.exe /TESTMANAGER /Execute tools\vanessa-automation-single.epf` с командой
`StartFeaturePlayer;QuietInstallVanessaExt;DisableFirstRunHelper;VAParams=<файл>`,
дожидается завершения и разбирает `junit.xml`.

## 5. Результаты прогона и критерий успеха

Каталог `reports/run-<дата-время>`:

| Файл | Содержимое |
| --- | --- |
| `junit.xml` | результаты по сценариям, основной источник для проверки |
| `status.txt` | `0` — все сценарии прошли |
| `steps.log` | пошаговый лог выполнения |
| `manager.log` | вывод менеджера тестирования, сюда смотреть при падении до старта |
| `screenshots/` | снимки при ошибках |
| `VAParams.json` | фактические параметры прогона |

Успех — одновременно: `status.txt` равен `0`, в `junit.xml` есть хотя бы один `testcase`
и ни у одного нет `failure`, `error`, `skipped`. Код выхода процесса сам по себе успехом
не считается. Раннер проверяет эти условия и бросает исключение с путем к отчету.

## 6. Ошибки и решения

| Сообщение или симптом | Причина и что делать |
| --- | --- |
| «Не найден клиент 1С (1cv8c.exe)» | платформа не в `Program Files`; укажите `-Exe` |
| «Несоответствие версий клиента и сервера» | клиент и сервер разных версий; `-Exe` на версию сервера |
| «Слишком длинный путь или имя файла» при распаковке | полный архив содержит глубокие каталоги; распакуйте в `$env:USERPROFILE` или берите минимальный набор из раздела 8 |
| «Расширение конфигурации с указанным именем не найдено» | расширение не загружено в эту базу; шаг 3 |
| «Ошибка блокировки информационной базы для конфигурирования» | открыт конфигуратор или монопольный сеанс; дождитесь освобождения, чужие сеансы не завершайте |
| «Неопределена информационная база» | неверная строка соединения: нужен вид `/S srv1\База`, форма `Srvr="...";Ref="...";` для `/S` не подходит |
| Нет `junit.xml`, `status.txt` пуст | менеджер не дошел до сценариев; смотрите `manager.log` |
| Тест-клиент не стартует, ошибка порта | порты заняты; задайте другой `-ClientPort` |
| Сценарий падает на первом шаге | имя TestClient в контексте не совпало с `-Profile`, либо нет такого объекта или заголовка окна |
| «Не найден шаг» / синтаксическая ошибка feature | проверьте `# language: ru`, табуляцию и кавычки в шагах |
| Шаги с внешней компонентой не работают | не загружено расширение `VAExtension` либо не выполнен `QuietInstallVanessaExt` |

## 7. Проверка, что все работает

Признак исправной установки: дымовой сценарий завершается статусом `0`. В проекте-источнике
это подтверждено отчетом `reports/run-20261102-213042`: 1 сценарий, статус 0, 11,9 с,
снимок формы «Демо: Организации» с тремя строками.

Сам архив проверен 02.11.2026 так: распаковка в `$env:USERPROFILE\va-kit-check` (все файлы),
затем прогон из распакованной копии. Результат — `Клиент: C:\Program Files\1cv8\8.3.27.2325\bin\1cv8c.exe`,
1 сценарий, статус 0. Отчет лежит в архиве: `reports/run-20261102-215242`. Клиент 8.5.1.1529
(без серверных компонентов) автоопределение не выбрало, что и требовалось.

## 9. Что не переносится как есть

- `scripts/onec.py` и va-скрипты источника рассчитаны на стенд хакатона: `stand.json` с УТ,
  `v8-runner`, `v8project.yaml`. В другом проекте они не работают, запуск дает только `va.ps1`.
- Сценарии в `features/` написаны для УТ 11 и профиля «УТ»; годятся как образцы приемов,
  но требуют адаптации объектов и заголовков.
- `extensions/ИнструментыVanessaСервер` содержит абсолютные пути стенда и не загружался
  ни в одну базу. Для переноса не нужен.
- `client_mcp.cfe` и настройки `mcp` — для интерактивного MCP-режима (порт 9874), он требует
  отдельной настройки менеджера и в этом проекте не поднимался.
