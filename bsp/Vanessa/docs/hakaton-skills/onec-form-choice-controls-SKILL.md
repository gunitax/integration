# Поля выбора в формах 1С

Пользователь должен видеть, что значение можно выбрать, и открывать выбор из
самого поля. Заполненный `СписокВыбора` и успешное присваивание значения через
код не доказывают, что кнопка есть на экране и работает.

## Выбрать подходящий элемент

Перед созданием или изменением формы перечислить поля с выбором, источник
вариантов, хранимый тип и допустимость ручного ввода.

| Данные поля | Ожидаемое поведение |
| --- | --- |
| Операция или режим с фиксированными вариантами | Видимая кнопка выпадающего списка; выбор из разрешённых вариантов; понятные названия |
| Сохранённая именованная настройка | Кнопка выбора существующих настроек; возможность ввести новое имя для сохранения |
| Справочник или другая ссылка | Доступная кнопка штатного выбора; представление выбранного объекта |
| Файл или каталог | Доступная кнопка соответствующего диалога выбора с подходящими ограничениями |
| Обычный свободный текст | Обычное поле ввода; искусственный список не нужен |

Для сохранённых настроек отдельные команды «Прочитать» и «Сохранить» не заменяют
выбор имени из доступных настроек. Пустой список не должен мешать созданию первой
настройки; сохранённая новая настройка должна появляться при следующем выборе.
Список формировать в рамках принятой в задаче области доступа пользователя.

## Реализовать выбор и представление

- Настроить именно элемент формы: кнопку, режим выбора, доступность и обработку
  результата. Не рассчитывать, что заполнение списка автоматически включит кнопку.
  Учесть видимость и доступность родительских групп и ширину поля.
- Разделять хранимое значение и представление. Например, ключ
  `СозданиеИРедактирование` может оставаться в логике, но на экране должно быть
  «Создание и редактирование номенклатуры». Проверить начальное значение,
  результат выбора, восстановление настройки и повторное открытие формы.
- Для закрытого набора вариантов не оставлять ввод произвольного технического
  ключа. Для имени новой настройки, напротив, сохранить допустимый ручной ввод.
  Не подменять неизвестное или устаревшее значение первым вариантом молча.
- Уточнять свойства, типы и контексты через справку установленной платформы
  и bsl-platform по [правилам проекта](../../../AGENTS.md). Свойства поля могут
  относиться к расширению конкретного вида элемента; отсутствие свойства
  в общей справке `ПолеФормы` само по себе не доказывает его недоступность.
- Для `bsl-platform` точное имя типа — `Расширение поля формы для поля ввода`
  (с пробелами). На этом стенде подтверждены `КнопкаВыпадающегоСписка`,
  `РежимВыбораИзСписка`, `РедактированиеТекста`; в XML это соответственно
  `DropListButton`, `ListChoiceMode`, `TextEdit`. Для строковых ключей операций
  режим выбора обеспечивает показ представлений из списка, а явная кнопка
  делает выбор видимым. У имени новой настройки не включать закрытый режим списка.
  XML и порядок узлов брать по [методике XML](../onec-extension-xml/SKILL.md).

## Проверить пользовательский выбор

Применять [цикл разработки](../onec-development/SKILL.md) и
[порядок согласования UI-проверки](../onec-task-triage/SKILL.md).
При разрешённом прогоне Vanessa проверить затронутые поля:

1. Открыть форму в свежем клиенте. Проверить понятное начальное представление.
2. Нажать именно кнопку выбора у поля и проверить открывшиеся варианты.
   Формулировку шага взять из библиотеки установленной Vanessa.
3. Выбрать другой вариант. Проверить представление в поле и соответствующее
   действие формы, затем проверить отмену выбора без потери прежнего значения.
4. Для настроек сохранить отдельную тестовую настройку, открыть её через выбор,
   проверить восстановление параметров и удалить только свои тестовые данные.
5. Закрыть и повторно открыть форму; проверить поведение по требованиям задачи.
   Снять средствами Vanessa реальный экран с раскрытым выбором и с выбранным
   значением по [методике UI](../onec-development/references/checks.md#ui).

Присваивание реквизита через код, серверный тест и выбор значения через API
тестирования не заменяют проверку видимой кнопки и открытия списка пользователем.
Не использовать сгенерированную картинку как свидетельство работоспособности формы.
Если UI-прогон не выполнялся, явно обозначить эту границу проверки.

Если полноэкранный захват Vanessa возвращает чёрный кадр, успех шага эмуляции
мыши сам по себе не подтверждает физический клик. Указать эту границу отдельно
от проверок штатным API тестирования. На этом стенде снимок окна через
`get_window_screenshot_os` подтверждал видимые кнопки, но закрывал раскрытый
список; не объявлять такой снимок доказательством открытого списка. При зависании
захвата всплывающего окна сохранить диагностику, завершить свои процессы по
правилам уборки и продолжить функциональный прогон в свежем клиенте.

Для изменения только этого скилла или ссылок на него достаточно проверки
документации; запускать базу и создавать искусственные тесты не требуется.
