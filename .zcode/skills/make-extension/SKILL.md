Создание и доработка расширений конфигурации. Основная конфигурация — поставляемая БСП, её не изменять: все доработки выполняются в расширениях (если явно не указано иное). Применение расширения к рабочей информационной базе — только по явной команде пользователя (см. «Запрещённые действия» в AGENTS.md).

## Состав и эталоны

- Расширения лежат в `src/extensions/<ИмяРасширения>/` — каждая папка является самостоятельной выгрузкой расширения (свой `Configuration.xml`).
- Эталоны: `src/extensions/_ДемоПустоеРасширение/` (минимальный состав: корень + `Languages/Русский.xml`) и `src/extensions/_ДемоРасширение/` (все виды объектов, заимствования, формы, роли). Живой пример: `src/extensions/КассовыеДокументы/` (документ + 2 формы + 2 роли + подсистема, создан 07.11.2026 и проверен загрузкой в тестовую базу).
- `ConfigDumpInfo.xml` руками не создавать и в новое расширение не копировать — Конфигуратор создаст при первом сохранении; фиктивные configVersion вызывают зависание «Загрузить из файлов».

## Корень Configuration.xml

- `Properties`: `ObjectBelonging = Adopted`; `ConfigurationExtensionPurpose` — `AddOn` («Дополнение», новые объекты) или `Customization` («Адаптация», правка форм/модулей основной конфигурации); `NamePrefix` — префикс собственных объектов; `ConfigurationExtensionCompatibilityMode` **не выше** `CompatibilityMode` основной конфигурации (здесь 8.3.24) — иначе расширение не подключается («Режим совместимости расширения больше режима совместимости основной конфигурации»); `ScriptVariant = Russian`.
- `InternalInfo`: `xr:PropertyState` для `CommandInterface` и `MainSectionCommandInterface` = `Extended`.
- `ChildObjects`: запись `<Language>Русский</Language>` + файл `Languages/Русский.xml` с `ObjectBelonging = Adopted` — без заимствованного языка синонимы `v8:lang = ru` не разрешаются и загрузка зависает.
- `DefaultRoles` в расширениях этой поставки не используется.
- UUID: корень и `ObjectId` в `ContainedObject` — новые для каждого расширения; `ClassId` — константы, копировать из эталона как есть.

## Объекты расширения

- Собственные — без `ObjectBelonging` в `Properties`, имя с префиксом `NamePrefix`.
- Заимствованные — `ObjectBelonging = Adopted` первым свойством и UUID объекта основной конфигурации (смена UUID = потеря связи с объектом).
- Ссылки на объекты основной конфигурации в собственных объектах (например `cfg:CatalogRef.Пользователи`) допустимы без заимствования.
- Кодировка всех XML/BSL расширения — UTF-8 с BOM, переводы строк CRLF (без BOM Конфигуратор не загрузит файл).

## Роли и права (Rights.xml)

- Права на перечисления не выдавать никогда: блок `<name>Enum.X</name>` в Rights.xml даёт бесконечное зависание загрузки на 8.3.27 (даже с одним правом Read), префикс `Enumeration.` не резолвится. В ролях БСП прав на перечисления нет ни разу — их и не нужно выдавать.
- Имена прав: изменение данных = `Update` (не `Edit`); `Edit` = «Редактирование»; права `InteractiveEdit` у справочников нет. Эталон состава прав: Read, Insert, Update, View, InteractiveInsert, Edit, InteractiveSetDeletionMark, InteractiveClearDeletionMark, InputByString (роль `_ДемоДобавлениеИзменениеНСИ`).
- У ролей `ChildObjects` отсутствует — норма.

## Ловушки формата выгрузки

- Reader XML строгий и последовательный: порядок элементов сверять с эталоном той же папки (в `UsualGroup` `ExtendedTooltip` идёт ДО `ChildItems`).
- Квалификаторы чисел в формах (`Forms/*/Ext/Form.xml`) — только формовый словарь: `v8:Digits`, `v8:FractionDigits`, `v8:AllowedSign` (`Nonnegative`/`Any`). Словарь метаданных (`v8:Precision`, `v8:NonNegative`) XDTO-ридер форм не читает: интерактивно — «Исключение XDTO… НачалоСвойства: Precision», пакетно — exit 1 с пустым /Out.
- У подсистемы блок `<ChildObjects/>` обязателен даже при пустом составе — без него «ошибка формата документа: ожидаемое ChildObjects».
- Ошибки прав на отсутствующие объекты дают чистый error, не hang; hang — только когда объекты резолвятся.

## Загрузка и проверка

- Вручную: Конфигуратор → Конфигурация → «Расширения конфигурации» → «Добавить» → «Загрузить из файлов» → папка расширения в `src/extensions/`. Обратно — «Выгрузить в файлы» в ту же папку.
- Статическая проверка до загрузки: скилл `cfe-validate` — `powershell -NoProfile -File .zcode/skills/cfe-validate/scripts/cfe-validate.ps1 -ExtensionPath <папка расширения> [-ConfigPath <каталог основной выгрузки>]`. Без XSD-схем проверяет структуру, с ними — ещё и формат (см. `THIRD-PARTY-NOTICE.md`).
- **Пакетная загрузка в тестовую базу — основной путь проверки** (по AGENTS.md: `File="C:\Users\sax\Documents\InfoBase22"`, Администратор, пароль пустой, платформа 8.5.1.1529). Скрипт `scripts/load-extension-infobase22.ps1` (значения зашиты внутри; для нового расширения — скопировать и заменить). Шаги: `/LoadConfigFromFiles <папка> -Extension <Имя>` (сам создаёт расширение) → `/UpdateDBCfg -Extension <Имя>` (применяет к данным, лог перечисляет «Новый объект: …») → проба `/DumpCfg <файл> -Extension <Имя>`.
- Scratch-база (изолированно, без тестовой): `1cv8 CREATEINFOBASE File=...` во `%TEMP%`, залить БСП `/LoadConfigFromFiles <корень репо>` (~7 мин), затем `/LoadConfigFromFiles <dir> -Extension <имя> /Out log`. Зависание загрузки диагностировать бисекцией состава. make-cfe/make-cf — см. их скиллы (make-cfe с кириллическим именем аргумента падает в фоновом вызове).
- Осторожно: убийство дизайнера посреди загрузки портит базу (дальше молча exit 1 с пустым логом — базу пересоздавать); `/Out` пуст = операция прошла чисто, упала до логирования ИЛИ команда не выполнилась вовсе (см. ловушки ниже).

## Ловушки пакетной загрузки (проверено 07.11.2026 на задаче КД_ПриходныйКассовыйОрдер)

- **Кириллические аргументы через cmd — холостые прогоны.** Кириллица (имя расширения, путь, пользователь), переданная через `cmd /c` и .cmd-батники, искажается: Конфигуратор молча не выполняет команду — exit 0, пустой `/Out`, в базе ничего не меняется. В фоновых вызовах искажение гарантировано. Обход: PowerShell-скрипт (UTF-8 **с BOM**, иначе PS 5.1 читает как ANSI) со значениями, зашитыми внутри, вызов платформы через `Start-Process -FilePath <1cv8> -ArgumentList <массив> -Wait -PassThru` — образец `scripts/load-extension-infobase22.ps1`.
- **`/CreateExtension` на 8.5.1.1529 молча не работает** (exit 0, пустой лог, расширения нет). Не использовать: расширение создаёт сама `/LoadConfigFromFiles <dir> -Extension <Имя>`.
- **`/DisableStartupDialogs` добавлять к DESIGNER всегда.** Без него при любой неоднозначности (в т.ч. ошибка авторизации) платформа открывает интерактивное окно Конфигуратора и запуск «зависает» навсегда.
- **DESIGNER выполняет только последнюю пакетную команду** в строке, остальные молча отбрасывает (проверено автором cc-1c-skills на 8.3.24). Одна операция — один запуск.
- **Пустой `/Out` при exit 0 ≠ успех.** Проба результата — `/DumpCfg <файл> -Extension <Имя>`: дамп прошёл (exit 0, файл > 0 байт) = расширение есть; «расширение с указанным именем не найдено» = нет.
- **Впервые загруженное расширение стартует с включённым безопасным режимом** — код модулей не применяется (`ОбработкаЗаполнения` и пр. молчат). Снять: `db-cfe-admin` (`set-properties -Name <Имя> -SafeMode "-"`) или вручную (Администрирование → Расширения).
- **Чужой процесс 1cv8 — сеанс пользователя: не убивать** (правило AGENTS.md). Свой зависший (открылся интерактивно от нашего запуска) можно останавливать по PID; по имени образа — никогда.
- **Shell-мелочи cmd:** многострочный `python -c` не работает — писать скрипт в файл; `;` в cmd НЕ разделитель команд (в одном случае `del` «съел» соседний файл); вывод цепочек через `&` может теряться — одна команда на вызов Bash.
- Альтернатива ручным цепочкам — скопированные скиллы cc-1c-skills: `db-load-xml` (загрузка + разбор лога на известные ошибки при exit 0), `db-update -Extension [-Dynamic on]` (обновление БД, в т.ч. без монопольного режима), `db-cfe-admin` (list/check/set-properties/delete расширений).

## Создание нового расширения

1. Скопировать `_ДемоПустоеРасширение` в `src/extensions/<Имя>/`, удалить его `ConfigDumpInfo.xml`.
2. В корне заменить UUID (корень и `ObjectId` в `ContainedObject`) и свойства: `Name`, `Synonym`, `NamePrefix`, `ConfigurationExtensionPurpose`, `ConfigurationExtensionCompatibilityMode`.
3. Добавить объекты по образцу `_ДемоРасширение` и `КассовыеДокументы`, сверяя порядок элементов с эталонами той же папки.
4. Проверить: `cfe-validate` → загрузка в тестовую базу (см. «Загрузка и проверка»); применение к рабочей базе — только пользователь.

## Грабли разработки и проверки (проверено 08–09.11.2026 на ЭТШ/ИТШ/СС_)

- **Режим совместимости расширения ≤ `CompatibilityMode` основной конфигурации** (НЕ по её `ConfigurationExtensionCompatibilityMode`!): для uf_demo ≤ 8.3.27 — значение `Version8_5_1` отвергается при `/UpdateDBCfg` (exit 101, «режим совместимости расширения должен соответствовать режиму совместимости конфигурации»).
- **Расширения самодостаточны**: `/CheckConfig` компилирует расширение изолированно — перекрёстные вызовы модулей ДРУГИХ расширений дают «Переменная не определена» (контексты Server/ExternalConnection), хотя в рантайме работает. Мелкие хелперы (JSON и т.п.) дублировать локально; от чужого расширения допустима зависимость только на бинарные общие макеты (строковые ссылки `ОбщийМакет.…` не проверяются компиляцией) и на данные.
- В клиентских модулях форм сообщать `Сообщить()`; `Новый СообщениеПользователя` в проверке тонкого клиента — «Тип не определен».
- **SafeMode=on и «Защита от опасных действий» включаются после ЛЮБОЙ загрузки** расширения (и `/LoadConfigFromFiles`, и `/LoadCfg` из .cfe) — блокируют ВК и `HTTPСоединение` («Установлен безопасный режим»). ibcmd отсутствует — снимать только в GUI Конфигуратора; перезагрузка расширения поверх существующего свойства сохраняет (снял один раз — держится).
- Точка входа через COM: проверять флаги `Server`/`ExternalConnection` у модулей по XML; через COM-диспетчеризацию доступны только экспортные модули расширений (глобальные `Выполнить`, `ПользователиИнформационнойБазы`, свойство `$q.Параметры` — NULL/DISP_E_UNKNOWNNAME — параметры запроса подставлять литералами в текст); нулевой результат InvokeMember проверять на `$null`; некаптурированные InvokeMember-вызовы в PowerShell-функциях утекают значения в выход (объект превращается в `Object[]`) — глушить `$null =`.
- HTTP-сервисы расширений публикуются только при `publishExtensionsByDefault="true"` в default.vrd (`publishByDefault` покрывает лишь сервисы основной конфигурации; симптом — 404 при живой публикации). Проверено на Apache: webinst пишет конфиг и без админ-прав, но старые блоки `<Directory "C:/Apache24/">` с `SetHandler 1c-application` наследуются на всё дерево — дескриптор может запрашиваться по корневому пути; при пустых 500 и stale-логах проверять, какой PID реально слушает :80.
- Vanessa-прогон форм расширений: шаги минимальные, поля не заполнять (значения по умолчанию из `ПриСозданииНаСервере` — «Начальная страница» перехватывает фокус через несколько секунд); шага «И я жду N секунд» нет (Pending); скриншоты после фоновых операций БСП — с серверной паузой; перед прогоном обмена — свежая порция в топике (офсеты группы потребителя живут в брокере, count-утверждения недетерминированы — проверять `Ошибок = 0` и содержимое справочника).
