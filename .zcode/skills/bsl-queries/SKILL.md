Работа с запросами 1С в этом репозитории. Два обязательных шага любого изменения запроса: (1) код по стандартам ИТС, (2) проверка, что поля условий и соединений проиндексированы в метаданных (std652). Здесь демонстрационная БСП 3.1: код на русском, стиль БСП, правки — текстом в выгрузке.

## Правила написания запросов (std729, std658)

Структура и объем:
- Запрос адекватен задаче: выбирать только нужные поля (не `*`) и только нужные строки (`ПЕРВЫЕ`, `РАЗЛИЧНЫЕ`, отбор).
- Никаких запросов в циклах — получать всё одним запросом (пакетом с временными таблицами).
- Большие выборки не выгружать в память (ТЗ/массив): обходить `Выборка = Запрос.Выполнить().Выбрать()`.
- Проверка существования записи — `ВЫБОР КОГДА ... ЕСТЬNULL` не нужен: брать `ПЕРВЫЕ 1` или соединение, а не `КОЛИЧЕСТВО(*) > 0` по всей таблице.
- Вложенные запросы в соединениях не использовать — временная таблица + `ИНДЕКСИРОВАТЬ ПО <поля соединения>`.
- `ОБЪЕДИНИТЬ ВСЕ` вместо `ОБЪЕДИНИТЬ`, если дубли допустимы (ВСЕ не строит уникальный индекс).

Условия и соединения:
- Поля в `ГДЕ`, в `ПО` соединений и в параметрах виртуальных таблиц — только проиндексированные (см. проверку ниже).
- В условиях не применять выражения к полям — отключает индекс: `НАЧАЛОПЕРИОДА(Дата, ДЕНЬ) = &Д` → `Дата >= &Начало И Дата < &Конец`; `ЕСТЬNULL(Поле, 0) = 0` → `(Поле = 0 ИЛИ Поле ЕСТЬ NULL)` (последнее — с оговоркой std708 про ИЛИ).
- `ИЛИ` по разным полям больших таблиц не использовать — разбивать на `ОБЪЕДИНИТЬ ВСЕ` (std708).
- `ПОДОБНО` с ведущим `%` — всегда скан всей таблицы; допустимо только на малых данных (std656).
- Условия и упорядочивание по полям через точку порождают скрытые соединения — соединять явно и индексировать поле соединения.
- Ссылочные поля составного типа разыменовывать через `ВЫРАЗИТЬ(... КАК Тип)` или явные соединения (std653).
- Условия к виртуальным таблицам (`СрезПоследних`, `Остатки`, `Обороты`...) — в параметрах виртуальной таблицы, не в `ГДЕ` (иначе читаются все записи).

Имена и псевдонимы:
- Псевдоним таблицы справочника не должен совпадать с именем измерения виртуальной таблицы — иначе неоднозначность разрешения имён (ошибки «Поле не найдено», ложное разыменование). Плохо: `Справочник.Номенклатура КАК Номенклатура` при соединении с `РегистрСведений.Цены.СрезПоследних` (измерение `Номенклатура`). Хорошо: `Справочник.Номенклатура КАК СпрНоменклатура`.
- Временные таблицы (`ПОМЕСТИТЬ`) — имя всегда с префиксом `ВТ_`: `ПОМЕСТИТЬ ВТ_ЦеныНоменклатуры`.

## Проверка индексов по выгрузке (std652)

Что проверять: все поля из `ГДЕ`, `ПО` соединений, параметров виртуальных таблиц и `УПОРЯДОЧИТЬ ПО` больших таблиц. Группировки (`СГРУППИРОВАТЬ ПО`) — выборочно, для больших таблиц.

Что не проверять (платформа индексирует всегда): `Ссылка` и ключевые поля объектных таблиц; `Регистратор` (и `Период`) в таблицах, подчинённых регистратору; ключ независимого регистра сведений (измерения + период в составе ключа).

Где лежат свойства полей — метаданные объекта это верхнеуровневый `<Раздел>/<Имя>.xml` (папка `<Имя>/` содержит только модули и формы):
- Справочники, документы, ПВХ: `Catalogs/<Имя>.xml`, `Documents/<Имя>.xml` — реквизиты и стандартные реквизиты.
- Регистры: `InformationRegisters/<Имя>.xml`, `AccumulationRegisters/<Имя>.xml`, `AccountingRegisters/<Имя>.xml` — измерения, ресурсы, реквизиты.

Как читать: у каждого поля в `<Properties>` есть тег `<Indexing>`:
- `Index` — индекс есть; `IndexWithAdditionalOrder` — есть (с доп. упорядочиванием);
- `DontIndex` — индекса нет (в этой выгрузке тег есть у всех полей, `DontIndex` — норма по умолчанию).

Быстрая печать пар «поле — индексирование» (cmd коверкает кириллицу — использовать PowerShell):

```
powershell -NoProfile -Command "Select-String -Path 'Q:\AIZCODE.SDD.SPECKIT\InformationRegisters\КурсыВалют.xml' -Pattern '<Name>|<Indexing>' | ForEach-Object { $_.Line.Trim() }"
```

(в выводе смотреть блоки полей; блоки форм/макетов из `ChildObjects` без `<Indexing>` игнорировать). Дополнительные индексы (`<Index>` в `ChildObjects`) в этой конфигурации не используются — каждый `<Indexing>` даёт однополевый индекс; для условий по комбинации полей индекс сработает по любому из них, но ведущее поле выбирать максимально селективное.

Если индекса нет:
1. Лучший вариант — переписать условие на индексированное поле или на поле с автоиндексом.
2. Если нужно само поле — выставить в XML `<Indexing>Index</Indexing>`: это правка свойства, не состава метаданных, текстом допустима (UTF-8 с BOM, CRLF, `uuid` не трогать, `ConfigDumpInfo.xml` не менять). Загрузка в Конфигуратор и применение к ИБ — только пользователь (см. «Запрещённые действия» AGENTS.md); на больших таблицах включение индекса вызывает реструктуризацию.
3. Если метаданные менять нельзя — допустимо оставить отбор по неиндексированному полю только на заведомо малых таблицах, указав это в ответе пользователю.

## Типовые ошибки (плохо → хорошо)

```bsl
// Плохо: выражение над полем убивает индекс
ГДЕ НАЧАЛОПЕРИОДА(Дата, ДЕНЬ) МЕЖДУ &Нач И &Кон
// Хорошо
ГДЕ Дата МЕЖДУ &НачалоПериода И &КонецПериода

// Плохо: срез последних с отбором в ГДЕ
ВЫБРАТЬ * ИЗ РегистрСведений.Цены.СрезПоследних ГДЕ Номенклатура = &Н
// Хорошо: отбор в параметре виртуальной таблицы
ВЫБРАТЬ ... ИЗ РегистрСведений.Цены.СрезПоследних(&Дата, Номенклатура = &Н)

// Плохо: соединение с подзапросом
ЛЕВОЕ СОЕДИНЕНИЕ (ВЫБРАТЬ ... ИЗ ...) КАК Вт ПО ...
// Хорошо: временная таблица с индексом
ВЫБРАТЬ ... ПОМЕСТИТЬ Вт; ИНДЕКСИРОВАТЬ ПО ПолеСоединения
```

## Грабли запросов и СКД (проверено на платформе 8.5.1.1529, 08–09.11.2026)

- **Функции `ЛЕВ` в языке запросов НЕТ** — только `ПОДСТРОКА(Поле, 1, N)`. Неизвестная функция не даёт внятной ошибки: `Выполнить()` падает `NullReferenceException` (через COM — без деталей, «Ссылка на объект не указывает»).
- **Сравнение неограниченных строк через `=` недопустимо** — тот же молчаливый `NullReferenceException`. Обход: `ПОДСТРОКА(Поле, 1, N)` с обеих сторон либо ограниченные длины реквизитов.
- `ВЫБОР` в условии `ПО` при ПОЛНОМ/ЛЕВОМ СОЕДИНЕНИИ допустим (проверено); поля NULL-стороны полного соединения в выражениях — оборачивать в `ЕСТЬNULL`.
- **Структура варианта СКД**: в группировке можно выбирать только поля с ролью `dcscom:dimension` или агрегаты — иначе «Поле X не может быть использовано в группировке Y» (схема загружается нормально, падает при формировании). Не-измеримые поля показывать детальными записями (`SelectedItemAuto`) внутри группировки по измерению.
- **8.5: у `ПроцессорКомпоновкиДанных` нет метода `Выполнить`** («Метод объекта не обнаружен» и в 1C, и через COM), при этом `КомпоновщикМакета.Выполнить` работает как в 8.3. Программную компоновку на 8.5 не проектировать без проверки API; отчёт проверять через форму БСП (`СформироватьОтчет` в `CommonForm.ФормаОтчета`) — формирование идёт в фоновом задании, перед скриншотом нужна пауза.
