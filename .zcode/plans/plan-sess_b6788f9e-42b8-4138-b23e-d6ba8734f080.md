# Сверка справочников «источник ↔ приёмник» отчётом из базы БСП

## Контекст

Товары уже передаются из БСП (`_ДемоНоменклатура`) в uf_demo (`Товары`) через Kafka-топик `goods` (расширения ЭТШ/ИТШ). Нужно на стороне БСП **отчётом** видеть, не разошлись ли справочники. Решения пользователя: приёмник отдаёт состояние через **HTTP-сервис в ИТШ**, охват — только товары, публикация — **на сервере Apache, публикацию выполняю я**. Существующие модули не меняем — только новые объекты; расширения самодостаточны (AGENTS.md п.11–13); UTF-8 BOM + CRLF.

Техническая база (разведка): скелеты отчёта СКД (`Report.xml` + `Templates/ОсновнаяСхемаКомпоновкиДанных/*`, тег `MainDataCompositionSchema`, DataSetQuery + parameter + settingsVariant «Основной», форма `CommonForm.ФормаОтчета` без своей), регистра сведений (Nonperiodical/Independent, порядок Resource→Attribute→Dimension), обработки с формой (4 файла). Публикация — `webinst.exe` из bin платформы + `default.vrd` с `<httpServices publishByDefault="true"/>`.

## A. uf_demo — HTTP-сервис в расширении ИТШ (новые объекты)

- `HTTPServices/ИТШ_Товары.xml` + `Ext/Module.bsl` — по образцу `uf_demo/src/HTTPServices/ОписанияТоваров.xml` (прочитать при реализации): RootURL `itsh-goods`, шаблон `/v1/goods`, метод GET. Модуль: запрос `Справочник.Товары` (не группы, не помеченные) → `ЗаписьJSON` → массив `[{Артикул, Наименование, Штрихкод, Описание}]`, ответ 200 `application/json; charset=utf-8`. JSON собирается локально в модуле сервиса (самодостаточность).
- Дополнить `ИмпортТоваровИзШины/Configuration.xml` (ChildObjects + HTTPService) — развитие нашего расширения, код не меняется.

## B. bsp — новое расширение `СверкаСправочников` (префикс `СС_`)

Папка `bsp/src/extensions/СверкаСправочников/` (AddOn, совместимость 8.3.21, DefaultRoles → `СС_ОсновнаяРоль`):

- **`CommonModules/СС_Сверка.xml` + Ext/Module.bsl** (Server+ExternalConnection): `ЗагрузитьСрез(АдресСервиса) Экспорт → Число` — `HTTPСоединение`+`HTTPЗапрос` GET, `ПрочитатьJSON`, ключ `КлючТовара(Артикул, Штрихкод, Наименование)` = `"А:"+Артикул` / `"Ш:"+Штрихкод` / `"Н:"+Наименование` (цепочка идентификации ИТШ с префиксом типа); атомарная перезагрузка регистра: `НаборЗаписей.Очистить()` + все записи + `Записать(Истина)` в транзакции.
- **`InformationRegisters/СС_СостояниеТоваровПриемника.xml`** — непериодический, Independent; измерение `Ключ` (строка 200); реквизиты `НаименованиеПриемника` (100), `АртикулПриемника` (20), `ШтрихкодПриемника` (13), `ОписаниеПриемника` (неогр.), `ДатаЗагрузки` (дата).
- **`Reports/СС_СверкаТоваров.xml` + СКД** — `ПОЛНОЕ СОЕДИНЕНИЕ` `Справочник._ДемоНоменклатура` ↔ регистр по вычислимому ключу (тот же `ВЫБОР` в запросе). Поля обеих сторон (источник сравнивается с обрезками приёмника: `Лев(Наименование,50)`, Артикул 15, Штрихкод 20), вычислимый **Статус**: `Совпадает / Расходится / Нет в приёмнике / Нет в источнике`. Вариант «Основной»: таблица деталей, отбор по умолчанию `Статус <> Совпадает` (снимаемый), колонка `ДатаЗагрузки`. `DefaultForm = CommonForm.ФормаОтчета`.
- **`DataProcessors/СС_ОбновлениеСреза.xml` + Forms/Форма… (4 файла)** — поле `АдресСервиса`, кнопка «Загрузить срез» → `СС_Сверка.ЗагрузитьСрез(Адрес)` → `Сообщить` итог (в клиентском коде только `Сообщить()`).
- `Languages/Русский.xml`, `Roles/СС_ОсновнаяРоль.xml`, `Subsystems/СС_СверкаСправочников.xml`. ВК нет — SafeMode не нужен.

## C. Развёртывание и проверка

1. Загрузить ИТШ-доработку в uf-demo-test (по образцу `ufdemo-ext.ps1`) + `/CheckConfig`.
2. **Публикация на Apache (делаю я)**: обнаружить Apache (служба/каталог, конфиг), `webinst.exe -apache24 -wsdir uf-demo-test -dir <htdocs> -connstr "File=C:\Users\sax\Documents\uf-demo-test" -confPath <httpd.conf>`, дописать в `default.vrd` `<httpServices publishByDefault="true"/>`, перезапустить службу Apache, проверить `Invoke-WebRequest http://localhost/uf-demo-test/hs/itsh-goods/v1/goods` → JSON. URL занести умолчанием в форму СС_.
3. Загрузить СС_ в InfoBase22 (по образцу `etsh-load.ps1`), `/CheckConfig` чисто.
4. Сквозная проверка: (а) штатный экспорт→импорт → срез → все «Совпадает»; (б) переименование товара в uf_demo (COM) → срез → «Расходится» с деталями; (в) пометка удаления товара в uf_demo → «Нет в приёмнике»; (г) новый товар в uf_demo → «Нет в источнике». Контроль статусов запросом (COM) по тексту запроса отчёта + визуальная проверка формы отчёта.
5. По успешной проверке: обновить AGENTS.md (механизм сверки, URL публикации) и память; коммит + push — по вашему подтверждению.
