# AGENTS.md — корневая инструкция проекта

## Что это за проект

`Q:\integration` — рабочая область для **интеграции двух конфигураций 1С** между собой. В корне лежат два самостоятельных подпроекта — XML-выгрузки конфигураций в формате Конфигуратора (не проекты 1C:EDT):

| Каталог | Конфигурация | Версия | Платформа / совместимость | Суть |
|---|---|---|---|---|
| `bsp/` | «БиблиотекаСтандартныхПодсистемДемо» (БСП 3.1) | 3.1.12.348 | 8.3, совместимость 8.3.24 | Демо-вендорская БСП: типовые подсистемы, ~3139 модулей .bsl |
| `uf_demo/` | «ДемонстрационноеПриложение» | 1.0.41.3 | 1С:Предприятие 8.5, совместимость 8.3.27, расширения 8.5.1 | Демо-торговая конфигурация: закупки, продажи, товарные запасы, финансы; план обмена «Мобильные», веб-сервис `MAExchange`, HTTP-сервисы, боты |

**Цель проекта — настроить обмен/интеграцию между этими двумя конфигурациями.** На стороне `bsp` есть готовый механизм — расширение `src/extensions/СервиснаяШинаПредприятия/` («СШП», префикс `СШП_`): шина данных поверх **Apache Kafka** через внешнюю компоненту librdkafka (нативные библиотеки лежат в общих макетах `CommonTemplates/librdkafka_win32|win64|linux32|linux64`). Состав: план обмена `ApacheKafka` (формы `ФормаУзла`, `ПараметрыТопика`), модули-обёртки ВК: `СервиснаяШинаПредприятияОтправитель` (продюсер: `Инициализировать`, `ОтправитьДанные`), `СервиснаяШинаПредприятияПолучатель` (консьюмер: `Инициализировать`, `Подписаться`, назначения), структуры сообщений — `СервиснаяШинаПредприятияКлиентСервер` (`Сообщение()`, `ПараметрыИнициализацииОтправителя()`, `ПараметрыИнициализацииПолучателя()`), плюс регламентное задание обмена, подписки на события, `СШП_ОсновнаяРоль`. Любые межконфигурационные решения реализовывать в расширениях соответствующего подпроекта, а не в основной конфигурации.

**Первый сквозной механизм реализован (08.11.2026): обмен товарами через Kafka-топик `goods`.**
- `bsp`: расширение `src/extensions/ЭкспортТоваровВШину/` (префикс `ЭТШ_`) — модуль `ЭТШ_ЭкспортТоваров.ВыгрузитьВсеТовары(Адрес, Топик)` выгружает справочник `_ДемоНоменклатура` в топик (порции по 100, сообщение `{Headers, Key=Артикул|Наименование, Value=JSON{Артикул, Наименование, Штрихкод, Описание}}`), обработка `ЭТШ_ВыгрузкаТоваров` с формой. ВК подключается из макетов СШП; модуль умеет использовать уже подключённую компоненту (fallback для внешнего соединения).
- `uf_demo`: расширение `src/extensions/ИмпортТоваровИзШины/` (префикс `ИТШ_`) — модуль `ИТШ_Шина` (обёртка консьюмера: ВК из собственных копий макетов `ИТШ_librdkafka_*`, подписка, пул, ручной коммит) и `ИТШ_ЗагрузкаТоваров.ЗагрузитьТовары(Адрес, Группа, Топик)` — идентификация товара **Артикул → Штрихкод → Наименование**, создание/обновление справочника `Товары` (Вид = Товар, обрезка длин 50/15/20), коммит офсетов только при порции без ошибок. Обработка `ИТШ_ЗагрузкаТоваров` с формой.
- Проверено на брокере `localhost:9092`: выгрузка из InfoBase22 → создание 2 товаров в uf-demo-test, повторный цикл обновляет без дублей.

**Второй механизм реализован (08.11.2026): сверка товаров отчётом из БСП.** Приёмник отдаёт состояние через HTTP-сервис: `uf_demo` — в расширении ИТШ HTTP-сервис `ИТШ_Товары` (RootURL `itsh-goods`, шаблон `/v1/goods`, GET → JSON-массив {Артикул, Наименование, Штрихкод, Описание}); публикация uf-demo-test на Apache (`C:\Apache24`, alias `/uf-demo-test`) — **`http://localhost/uf-demo-test/hs/itsh-goods/v1/goods`**; для публикации HTTP-сервисов РАСШИРЕНИЙ в default.vrd обязателен атрибут `publishExtensionsByDefault="true"` (publishByDefault публикует только сервисы основной конфигурации); дескриптор публикации лежит в двух местах (htdocs и корень Apache — старый блок `<Directory "C:/Apache24/">` с SetHandler перехватывает). В `bsp` — расширение `СверкаСправочников` (префикс `СС_`): модуль `СС_Сверка.ЗагрузитьСрез(Адрес)` (HTTP→регистр) + `ЗагрузитьСрезИзJSON(СтрокаJSON)` (запись без HTTP, для headless-прогонов), регистр `СС_СостояниеТоваровПриемника` (ключ = `А:артикул`/`Ш:штрихкод`/`Н:наименование` — та же цепочка, что в ИТШ), отчёт СКД `СС_СверкаТоваров` (ПОЛНОЕ СОЕДИНЕНИЕ справочника с регистром по ключу, Статус: Совпадает/Расходится/Нет в приёмнике/Нет в источнике, отбор по умолчанию Статус <> Совпадает, форма `CommonForm.ФормаОтчета`), обработка `СС_ОбновлениеСреза` (кнопка «Загрузить срез»). Все 4 статуса проверены сквозным прогоном через COM. Грабли СКД/HTTP — в памяти (1c-extension-pitfalls).

## Иерархия инструкций — обязательно читать дальше

Каждый подпроект имеет собственный `AGENTS.md` с детальными правилами. При работе внутри подкаталога **его AGENTS.md обязателен к исполнению**:

- [`bsp/AGENTS.md`](bsp/AGENTS.md) — формат выгрузки 2.20, структура каталогов, стиль БСП, работа с расширениями, Vanessa Automation, запрещённые действия, тестовая база.
- [`uf_demo/AGENTS.md`](uf_demo/AGENTS.md) — структура выгрузки (формат 2.21), расширения `ВесТоваров` (префикс `ВТ_`) и `Колонтитулы` (префикс `КОЛ_`), правило «без ё в именах метаданных».

При противоречии правила подпроекта приоритетнее общих правил этого файла для файлов внутри него.

## Общие правила (действуют на весь проект)

1. **Всегда отвечать на русском языке.**
2. **Разработка — только в расширениях** (`src/extensions/<ИмяРасширения>/`). Основную конфигурацию (`src/Configuration.xml`, каталоги объектов) не менять без явного указания пользователя.
3. **Формат файлов выгрузки:** UTF-8 **с BOM**, переводы строк **CRLF** (проверено в обоих подпроектах). Без BOM Конфигуратор не загрузит файл.
4. **UUID в XML не менять** — они идентифицируют объекты в информационной базе; смена = потеря данных при обновлении.
5. **`ConfigDumpInfo.xml` не редактировать вручную** — его ведёт Конфигуратор.
6. **Состав объектов метаданных** (добавление/удаление файлов объектов) меняется только через Конфигуратор с последующей выгрузкой в файлы; правки «в лоб» по XML сломают загрузку.
7. **Не использовать букву «ё» в именах метаданных** (`Name`); синонимы (`Synonym`) могут содержать «ё».
8. **Префиксы новых объектов** — по `NamePrefix` своего расширения (примеры: `КД_` в `bsp/КассовыеДокументы`, `СШП_` в `bsp/СервиснаяШинаПредприятия`, `ВТ_`/`КОЛ_` в `uf_demo`). Заимствованные объекты именуются без префикса и с UUID основной конфигурации (`ObjectBelonging = Adopted`).
9. **Режим совместимости расширения** (`ConfigurationExtensionCompatibilityMode`) — не выше режима основной конфигурации (`CompatibilityMode`): для `bsp` ≤ 8.3.24, для `uf_demo` ≤ **8.3.27** (значение `Version8_5_1` платформа отвергает при применении: «режим совместимости расширения должен соответствовать режиму совместимости конфигурации»).
10. **Веб-поиск** — в конце ответа приводить раздел «Sources:» с markdown-ссылками на использованные источники.
11. **Писать код по принципам SOLID, DRY и KISS**: одна ответственность на модуль/процедуру; общую логику не дублировать, а выносить в переиспользуемые функции; решение — минимально достаточное, без избыточных абстракций и «на будущее».
12. **Существующие модули не изменять** — новый код писать в новых модулях/процедурах. Правки существующих модулей (общих, объектных, модулей форм) — только по явному указанию пользователя.
13. **Расширения самодостаточны**: не вызывать общие модули других расширений — `/CheckConfig` компилирует расширение изолированно, перекрёстные ссылки дают «Переменная не определена» (мелкие хелперы — локальные копии). В клиентском коде форм сообщать через `Сообщить()`; `Новый СообщениеПользователя` в проверке тонкого клиента даёт «Тип не определен».
14. **Синтаксический контроль расширений** (применимость + модули в контекстах ThinClient/Server/ExternalConnection + целостность конфигурации): `powershell -File bsp\.zcode\skills\db-cfe-admin\scripts\db-cfe-admin.ps1 -Command check -InfoBasePath <база> -Name <Имя> -Checks apply,modules,config -Context ThinClient,Server,ExternalConnection`.

## Запрещённые действия (оба подпроекта)

- **Не завершать сеансы пользователей** — ни при каких операциях (даже требующих монопольного режима). Если операция блокируется пользователями — сообщить и ждать решения пользователя.
- **Не применять расширения к рабочим базам автоматически** — только по явной команде. Исключение: тестовая база `InfoBase22` для `bsp` (см. `bsp/AGENTS.md`).
- Не трогать бинарные файлы выгрузок (`*.bin`, картинки `CommonPictures/`).
- Кириллицу в аргументы `1cv8`/`V8.com` из cmd передавать нельзя — значения зашивать в `.ps1`-файлы (UTF-8 с BOM).
