# AGENTS.md — правила работы с проектом

## О проекте

`D:\AI.V6\uf_demo` — выгрузка конфигурации **1С:Предприятие 8.5** в XML-формате Конфигуратора.

- Конфигурация: **ДемонстрационноеПриложение** («Демонстрационное приложение»), версия 1.0.41.3, вендор Фирма «1С».
- Режим: управляемое приложение, язык скриптов — русский, режим совместимости расширений — Version8_5_1.
- Назначение: демонстрационная торговая конфигурация (закупки, продажи, товарные запасы, финансы) с мобильным приложением: план обмена «Мобильные», веб-сервис `MAExchange`, HTTP-сервисы, push-уведомления, геопозиционирование, боты (система взаимодействия).

## Обязательные правила

1. **Всегда отвечать на русском языке.**
2. **Разрабатывать только в расширениях.** Все доработки выполняются в расширениях конфигурации (папка `src/extensions`). При необходимости — создавать **новое** расширение. Основную конфигурацию (`src/Configuration.xml`, каталоги объектов конфигурации) **без явного указания пользователя не менять**.
3. **Не использовать букву «ё» в именах метаданных** (`Name`). Например: «Расчеты», а не «Расчёты». Синоним (`Synonym`) может содержать «ё».
4. **При веб-поиске всегда приводить прямые ссылки на источники**, из которых получена информация.

| `extensions/ИмпортТоваровИзШины` | `ИТШ_` | приём товаров из Kafka (топик `goods`, группа `uf-demo-goods`, обмен с БСП): консьюмер `ИТШ_Шина` (ВК librdkafka из собственных макетов `ИТШ_librdkafka_*`, ручной коммит), `ИТШ_ЗагрузкаТоваров` (идентификация Артикул → Штрихкод → Наименование, справочник `Товары`) и его обработка; **HTTP-сервис `ИТШ_Товары`** (RootURL `itsh-goods`): GET `/v1/goods` — товары, GET `/v1/orders` — заказы с товарными строками |
| `extensions/ИмпортСчетовИзШины` | `ИСШ_` | приём счетов из Kafka в заказы (топик `invoices`, группа `uf-demo-invoices`, обмен с БСП): консьюмер `ИСШ_Шина` (макеты `ИСШ_librdkafka_*`), `ИСШ_ЗагрузкаСчетов` (заказ по паре «номер+дата», ТЧ полностью, без проведения, состояние «Открыт», новые элементы не создаются, ненайденное — пропуск + протокол), `ИСШ_ТестовыеДанные` (фикстуры Vanessa через COM к InfoBase22), `ИСШ_ОбменСчетами` (подсистема), `ИСШ_ОсновнаяРоль` |

## Сторона приёмника в обменах с БСП и HTTP-сервис сверки

Приёмник (`uf_demo`) участвует в двух сквозных обменах из `bsp` (БСП) через Kafka на `localhost:9092` и отдаёт состояние для сверок:

- **Приём товаров** — расширение `ИмпортТоваровИзШины`: обработка `ИТШ_ЗагрузкаТоваров.ЗагрузитьТовары("localhost:9092", "uf-demo-goods", "goods")`.
- **Приём счетов в заказы** — расширение `ИмпортСчетовИзШины`: обработка `ИСШ_ЗагрузкаСчетов.ЗагрузитьСчета("localhost:9092", "uf-demo-invoices", "invoices")`.
- **HTTP-сервис сверки** (нужен отчётам `СС_СверкаТоваров`/`СС_СверкаЗаказов` из БСП) — `ИТШ_Товары` в расширении `ИмпортТоваровИзШины` (RootURL `itsh-goods`): шаблон `Товары` (GET `/v1/goods`) и шаблон `Заказы` (GET `/v1/orders`, шапки заказов + товарные строки). Адреса при публикации uf-demo-test на Apache (`C:\Apache24`, alias `/uf-demo-test`): **`http://localhost/uf-demo-test/hs/itsh-goods/v1/goods`** и **`.../v1/orders`**. Для публикации сервисов РАСШИРЕНИЙ в default.vrd обязателен `publishExtensionsByDefault="true"`; дескриптор публикации лежит в двух местах (htdocs и корень Apache).
- После первой загрузки ИТШ/ИСШ в базу снять в Конфигураторе «Безопасный режим» и «Защиту от опасных действий» (подключение ВК librdkafka).

Правила работы с расширениями:

- Новое расширение создается по образцу существующих: папка `src/extensions/<ИмяРасширения>/` с собственным `Configuration.xml` (uuid, `Name`, `NamePrefix`) и каталогами типов метаданных.
- Новый объект расширения должен иметь префикс расширения (задан в `NamePrefix`); заимствованные из конфигурации объекты именуются без префикса.
- Не менять uuid-ы объектов и не редактировать `ConfigDumpInfo.xml` вручную — их ведет Конфигуратор.

## Формат файлов

- Каждый объект метаданных — `<Каталог>/<Имя>/<Имя>.xml` + при наличии реквизитов/форм вложенная структура (`Forms/`, `Templates/`, `Ext/`).
- Модули на встроенном языке 1С — файлы `.bsl`.
- Формы — `.../Forms/<ИмяФормы>.xml` (описание) и `.../Forms/<ИмяФормы>/Ext/Form.xml` (модуль и элементы).
- Весь текст в файлах — UTF-8.
